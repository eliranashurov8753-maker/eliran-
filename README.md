# זריז / שליח + — חבילת פריסה (Deploy)

חבילה זו מריצה את האפליקציה על שרת אמיתי, כך שתצורת החנות (לוגו, שם, תיאור, מוצרים) **משותפת בין כל המשתמשים והמכשירים** — עסק מעלה לוגו במכשיר שלו, והלקוח רואה אותו במכשיר שלו.

## מבנה התיקייה (חשוב מאוד!)
כדי שלא תקבלו שוב את השגיאה `Cannot find module server.js`, המבנה חייב להיות בדיוק כך — **server.js ו-package.json ברמה העליונה, ו-index.html בתוך תיקיית public**:

```
zariz-deploy/
├── server.js
├── package.json
├── README.md
└── public/
    └── index.html
```

---

## פריסה ל-Render דרך GitHub (ללא טרמינל)

### שלב 1 — העלאת הקבצים ל-GitHub
1. היכנסו ל-github.com והתחברו (או פִּתחו חשבון).
2. לחצו על **New** ליצירת מאגר (repository) חדש. תנו שם, למשל `zariz`, ולחצו **Create repository**.
3. במסך המאגר החדש לחצו על **uploading an existing file** (הקישור "upload an existing file").
4. גררו לתוך החלון את **server.js**, את **package.json** ואת **README.md**.
5. גררו גם את תיקיית **public** (שבתוכה index.html). אם GitHub לא מאפשר לגרור תיקייה — צרו קובץ בשם `public/index.html`: לחצו **Add file → Create new file**, ובשדה השם כתבו `public/index.html`, הדביקו את תוכן ה-index.html, ולחצו **Commit**.
6. לחצו **Commit changes**. עכשיו כל הקבצים במאגר.

### שלב 2 — חיבור ל-Render
1. היכנסו ל-render.com והתחברו עם חשבון GitHub.
2. לחצו **New + → Web Service**.
3. בחרו את המאגר `zariz` שהעליתם.
4. מלאו את ההגדרות:
   - **Name**: כל שם (למשל zariz)
   - **Root Directory**: **השאירו ריק** (כי server.js נמצא ברמה העליונה של המאגר). *אם בטעות שמתם את הקבצים בתוך תת-תיקייה בשם zariz-deploy — כתבו כאן `zariz-deploy`.*
   - **Runtime / Environment**: Node
   - **Build Command**: `npm install`
   - **Start Command**: `node server.js`
   - **Instance Type**: Free
5. לחצו **Create Web Service**. Render יבנה ויעלה — אחרי דקה-שתיים תקבלו כתובת כמו `https://zariz.onrender.com`. פִּתחו אותה — האפליקציה עובדת.

## חשוב: שמירה קבועה של הנתונים
בחבילה זו הנתונים המשותפים נשמרים בקובץ `db.json` על השרת.

- ב-**Render בתוכנית החינמית** מערכת הקבצים היא זמנית: בכל פריסה מחדש או "הרדמה" של השירות (אחרי חוסר פעילות) הקובץ מתאפס. הלוגו/מוצרים שהוגדרו עלולים להימחק בעת רסטרט.
- **הפתרון לשמירה קבועה**: הוסיפו ל-Render דיסק קבוע (Persistent Disk) והפנו אליו את הנתונים:
  1. בעמוד השירות ב-Render → לשונית **Disks** → **Add Disk**.
  2. **Mount Path**: `/data` · **Size**: 1GB.
  3. לשונית **Environment** → **Add Environment Variable**: `DB_FILE` = `/data/db.json`.
  4. שמרו — השירות יעלה מחדש והנתונים יישמרו לצמיתות.
- הערה: דיסק קבוע הוא לרוב תכונה בתשלום ב-Render. ללא דיסק, האפליקציה עדיין עובדת — רק שהנתונים המשותפים עלולים להתאפס בעת רסטרט. גם ללא שרת בכלל, כל שינוי עדיין נשמר מקומית בדפדפן של המשתמש.

## עדכון האפליקציה בעתיד
כשאני שולח לכם `index.html` מעודכן: החליפו את הקובץ `public/index.html` במאגר ב-GitHub (Add file → העלאה / עריכה) ולחצו Commit. Render יזהה את השינוי ויעלה גרסה חדשה אוטומטית.

## מה משותף ומה מקומי (בשלב הנוכחי)
- **משותף בין כל המכשירים** (דרך השרת): תצורת החנות — לוגו, שם, תיאור ומוצרים.
- **מקומי לכל מכשיר/דפדפן**: פרופיל הלקוח, כתובות, מצב השליח/עסק, וההזמנות הפעילות.
- השלב הבא המומלץ: להעביר גם את **ההזמנות** לשרת, כדי שהזרימה לקוח → עסק → שליח תתעדכן בזמן אמת בין מכשירים שונים.
